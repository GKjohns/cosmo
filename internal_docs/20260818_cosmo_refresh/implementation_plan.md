# Cosmo Refresh — Implementation Plan

**Created:** August 18, 2026
**Status:** In Progress — executing 2026-08-18 (Kyle: "yes to all, just don't go overboard"; push per sprint; lean path — optional items dropped)
**Context:** Cosmo is the starter every new Monument Labs project is rsync'd from, so whatever cosmo ships, every future project inherits. Three research passes on 2026-08-18 (audit of cosmo as it stands, best-practice fold-back from Camera Shy / Daylight / Monument / Personal site, and a diff against the six Nuxt UI templates) found that cosmo (a) does not build — a demo-mode redirect loop OOMs the prerender crawler, and nuxt-og-image 5.x 400s on Nuxt ≥4.5, (b) has drifted from the auth / analytics / SEO / AI-SDK canon that the shipped apps converged on, and (c) is one major AI SDK version and one Nuxt UI minor behind the templates it was built from. Kyle's ask: fold the shipped apps' best practices and the templates' better patterns back into cosmo.

**Goal:** A fresh `rsync` of cosmo, followed by `project_bootstrap.md`, gives a new project a repo that builds green, boots with zero `.env`, and already matches the auth / analytics / SEO / AI-Gateway / repo-shape canon that Camera Shy and Daylight ended up at — so no future project re-learns any of it.

**Scope:**
- **In:** repo shape (`src/` + root docs/migrations), build/typecheck/lint green, dependency refresh (nuxt 4.5.2 commit, `@nuxt/ui` 4.10, `ai@7` / `@ai-sdk/vue@4`, `@nuxt/content` 3.15), auth block → Camera Shy's canon files, analytics schema + typed events + error capture + `/internal`, SEO/head + brand-asset set + routeRules, gateway-only AI, Stripe idempotency + Inngest conventions, vitest harness + CI, chat/editor/marketing-shell parity with the Nuxt UI templates, docs (CLAUDE.md, README, internal_docs index, gateway-usage mirror) and the exact edits the central convention docs need.
- **Out:** live-Supabase verification (cosmo has no project; the bootstrap dry-run is the acceptance test), any product feature (coupons, share links, votes, file uploads, realtime voice), the analyst bot, Yjs collab, a bespoke landing page. See "Considered and rejected" and "Deferred".

**Research inputs (read for detail, not required to execute):** `r1_cosmo_audit.md`, `r2_best_practices.md`, `r3_templates_vs_cosmo.md` — copies live in this folder under `research/`.

## Considered and rejected
- **`nuxt-og-image` 6.x (Takumi) instead of removal.** Every shipped app serves a static 1200×630 `og-image.png`; the bootstrap doc names that as the reference; v6 needs a native renderer dep and a component rename, and v5 is what broke on Nuxt ≥4.5. A template should carry the fleet default. Per-post OG cards are a per-project add (documented in CLAUDE.md landmines).
- **Keeping the app at the repo root** (skip the `src/` move). Both shipped SaaS apps and both cosmo-derived clones (`project-aide`, `CommunityNavigator`) ended up at `src/` by hand — every clone pays the move; do it once in the template. Cost is one `git mv` commit.
- **Keeping prerender for content pages.** The crawler caused the OOM and turns dead links into build failures; Daylight's `/` lesson means `/` can't be prerendered anyway. Opt-in per project.
